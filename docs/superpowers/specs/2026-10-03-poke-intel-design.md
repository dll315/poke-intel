# Poke 情报站：首版设计

日期：2026-10-03

## 已确定的目标

建设公开的中文 PokeMMO 情报网站，手机和电脑均可使用。任何人可以浏览；用户以邮箱和密码注册登录后可以上报；管理员审核后公开展示。首版实现实时情报、历史查询、玩家上报、管理审核。部署目标为用户现有中国大陆 Ubuntu 轻量服务器（4 核、4 GB 内存），使用已备案域名。微信小程序留作下一阶段，共用接口。

## 实现方式与取舍

采用 React + TypeScript + Vite 构建网页，Node.js + Fastify 提供 JSON API，SQLite 保存账号、会话、报告、事件和审核日志，Nginx 提供 HTTPS 和反向代理。Docker Compose 管理网页代理及应用，数据库置于持久化目录。该方案便于在单台服务器部署与备份，适合首版；持续写入量增长后可以迁移 PostgreSQL。

另两种可行方式是服务端模板网页和独立网页/小程序后台。前者部署简单，但不如当前方案便于后续复用交互；后者增加重复逻辑和运维负担。首版选择一个后台服务和一套网页。

## 页面与交互

### 首页

暂定站名“Poke 情报站”，采用浅色中文工具界面，以情报卡片为核心；手机单列、电脑多列。提供头目/群聚分类、地区筛选、宝可梦与地点搜索，卡片显示名称、地区、地点、报告时间、来源、最后确认时间和状态。网页可每 60 秒检查更新，并提供手动刷新、最近成功更新时间和请求失败提示。全部时间以北京时间显示，底层保存 UTC。

默认仅展示已审核且处于有效状态的事件；“已审核”描述平台审核结果，不宣称游戏中独立验证。没有真实情报时显示空状态和上报入口。演示数据只在独立演示模式启用，每张卡片明确标为示例，正式环境默认禁用。

### 历史查询

展示审核通过的有效、已结束和已纠错事件。支持宝可梦名称、地区、日期范围、类型与状态筛选，按报告时间倒序分页（每页 20 条）。展示来源与纠错信息，筛选条件可保存在网址。时间筛选按北京时间的日期边界转换 UTC。

### 注册、登录与上报

用户输入邮箱和密码注册；邮箱作为登录标识，首版不接入邮件验证或自动密码找回，也不宣称邮箱已验证。用户可使用昵称公开署名，邮箱不公开。密码不少于 10 位，通过 scrypt 加盐哈希保存。

登录后提交类型（头目/群聚）、宝可梦名称、地区（关都/城都/丰缘/神奥/合众）、地点、观察时间、说明。观察时间不能在未来或早于当前 24 小时；名称与地点有长度限制；说明按纯文本显示。每位用户每分钟最多提交 3 次、每日最多 50 次。待审记录不公开，用户在“我的上报”查看审核状态和驳回理由。首版不上图片，避免新增上传和存储复杂度。

### 管理后台

仅管理员访问。提供待审队列、通过、驳回及理由、编辑已发布情报、标记结束、停用/恢复账号。禁止停用最后一个管理员，停用账号立即撤销其会话。审核动作、事件修改及账号状态变更写入审计日志。待审数据不会由普通列表接口泄露。

通过审核时可设置有效截止时间（默认观察时间后 60 分钟，可修改；此时间是网站展示规则而非游戏机制）。超过截止时间自动归入已结束，管理员也可手动结束。重复报告在审核时合并到同一有效事件：同类型、地区、宝可梦和地点且观察时间相差不超过 15 分钟；保留每个原始报告与贡献者，更新最后确认时间。不能仅按宝可梦去重，以免把不同地点的事件误合并。

## 数据和来源

自有玩家上报为首版可用数据源。报告与公开事件分开存储，审核可以关联或新建事件，来源标签明确区分“本站玩家”“外部来源”“示例”。历史保留原始来源和变更记录。

外部来源设置独立适配器边界，接收包含 source、sourceEventId、kind、pokemon、region、location、observedAt、expiresAt、sourceUrl 的规范化记录，以 source + sourceEventId 幂等导入。导入内容也进入审核流程。只有核实可用接口与使用许可并配置后才启用；首版默认关闭，不静默抓取，不伪造同步成功。未接入时界面明确说明“外部情报尚未接入”。当前读取到 Alphapedia 条款主要针对 Discord Bot，不能视为数据再发布许可。

## API 和数据边界

接口统一置于 /api/v1，后续微信小程序复用。公开读取包括 /events、/events/:id 和 /status；身份接口包括 /auth/register、/auth/login、/auth/logout、/auth/me；上报包括 /reports 和 /reports/mine；管理员使用 /admin/reports、/admin/events、/admin/users。

核心表：users（邮箱、昵称、密码哈希、角色、状态）、sessions（令牌哈希、到期时间、用户）、reports（上报内容、来源、审核状态、关联事件）、events（公开事件、状态、有效截止、最后确认）、audit_logs（操作者、动作、对象、时间）。数据库查询使用参数绑定。

所有写入接口执行角色和账号状态检查。网页使用 HttpOnly、SameSite=Lax 会话 Cookie；生产环境启用 Secure，服务端校验写入请求 Origin 并使用 CSRF token。会话 7 天过期，登录防暴力尝试，密码与会话令牌不写入日志。未来小程序认证另行设计，本轮不暴露持久访问令牌。

## 失败处理与可用性

请求失败保留当前视图并提示重试，显示最后成功更新时间；旧数据不会无标识地呈现为实时更新。登录过期引导重新登录，403 显示无权限，422 在相关字段展示错误，429 显示稍后再试。提交与审核在事务中完成；重复点击不会产生两个公开事件。数据过期由读取逻辑及后台维护共同处理，服务重启不影响正确状态。

界面有明确标签、键盘焦点和状态文字，状态不只依赖颜色，触控按钮适合手机使用。站点不使用 Discord 登录作为首版依赖，不要求大陆用户访问境外 CDN 才能操作核心功能。

## 部署与交付

交付源码、环境变量示例、Docker Compose 配置、Nginx HTTPS 配置示例、管理员初始化命令、数据库备份/恢复说明和中文部署指南。初始管理员由部署者运行命令创建，无默认密码。生产配置要求指定域名/站点 Origin，示例与开发配置不自动用于公网。数据库目录持久化，建议每日备份，备份文件不可被网页公开下载。

尚缺的部署输入是具体域名及服务器访问方式；不在文档保存密码或密钥。开发和本地验证可先完成，真实部署需要这些输入。未实际部署前不宣称已上线。

## 验收

1. 未登录用户可浏览与筛选，不能提交或调用管理员接口。
2. 注册登录、登出、停用账号、会话过期均符合权限边界。
3. 上报默认待审，通过后公开；驳回有原因；普通用户不能审核。
4. 同地点重复报告按规定合并，不同地点保留；审核日志和原始报告可追溯。
5. 过期与手动结束事件从首页移入历史，日期筛选正确处理北京时间边界。
6. 输入验证、限流、密码哈希、CSRF 与 HTML 转义接受实际测试。
7. 手机和桌面完整走通浏览、登录、上报、审核、历史查询，包含空状态与网络错误。
8. 生产构建成功；数据重启持久化；部署配置和备份流程可验证。

## 本轮范围之外

微信小程序、推送通知、图鉴、捕获率计算、育种工具、图片上传、付费功能及未经授权的数据同步均不属于首版。它们不作为完成上述首版的前提。
